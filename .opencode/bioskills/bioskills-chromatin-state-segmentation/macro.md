# Bioskills Chromatin State Segmentation

## Overview

Chromatin state segmentation integrates a panel of histone modification ChIP-seq tracks into a small set of recurring combinatorial patterns (chromatin states) — active promoter, active enhancer, poised/bivalent enhancer, polycomb-repressed, heterochromatic, transcribed, quiescent — and segments the genome by which state each region belongs to. Inputs: aligned histone mark ChIP-seq BAM files (minimum 4–5 marks, e.g. H3K4me3, H3K27ac, H3K4me1, H3K36me3, H3K27me3) with matched sonicated input controls, plus a chromosome sizes file. Outputs: per-state genomic intervals (BED), a state-by-mark emission matrix, a state-state transition matrix, and optionally functional enrichment of each state against external feature sets. Use this workflow when you have a panel of histone marks and want a genome-wide, interpretable segmentation into regulatory states; with fewer than ~4 marks, simpler peak-based annotation is more appropriate. ChromHMM (multivariate HMM on binarized 200 bp bins) is the de facto standard; Segway offers continuous-signal segmentation, EpiSegMix flexible read-count distributions, IDEAS cell-type-aware joint inference, EpiLogos multi-biosample visualization, and the full-stack ChromHMM a precomputed 100-state cross-tissue model. Reference examples tested with ChromHMM 1.27+, Segway 3.0+, EpiSegMix 1.0+, EpiLogos, IDEAS 1.20+, samtools 1.19+, bedtools 2.31+; ChromHMM requires Java 8+ and runs as `java -mx<MEMORY> -jar ChromHMM.jar <command>`.

## Preparation & Binarization

Set up the input panel and binarize ChIP-seq signal into the discrete representation ChromHMM's HMM consumes. Build a cell-mark-file table listing each cell type, histone mark, BAM file, and optional input control. Run ChromHMM BinarizeBam to convert aligned BAMs into fixed-width genomic bins (default 200 bp), assigning each bin a binary 0/1 per mark based on whether signal exceeds a Poisson threshold relative to the control. This binarization is the foundation for the multivariate HMM. Ensure all BAMs are indexed beforehand (BinarizeBam is very slow on unindexed BAMs) and use sonicated input — not IgG — as the control for histone marks, since ChromHMM's binarization assumes input background. Output: per-chromosome binary text files, one row per 200 bp bin, columns = marks, values 0/1.

## Model Learning

Train the multivariate HMM to learn chromatin states from the binarized signal. Run ChromHMM LearnModel with a chosen state count N. The model jointly estimates a state-by-mark emission matrix and a state-state transition matrix, and automatically produces per-chromosome segment BED files plus emission/transition visualizations. State count should match the mark panel size: 8–10 states for 3–5 marks (initial exploration), 15 for the 5 core Roadmap marks (canonical), 18 for 5–7 marks (adds bivalent and fine enhancer subtypes), 25 for 6+ marks (Roadmap extended, cross-cell-type compatible). Train at several N values and inspect emission-matrix similarity to choose the smallest N where states are interpretable as distinct biology — excess states fragment biology into redundant emission profiles, while too few states lump unrelated regions together.

## State Interpretation

Assign biological meaning to each learned state by reading the emission matrix. Each state's emission profile (which marks are on or off) maps to a known regulatory category. The Roadmap 15-state model provides canonical assignments spanning active TSS, flanking TSS, transcribed regions, enhancers, bivalent TSS/enhancers, polycomb-repressed, heterochromatin, and quiescent. Inspect the emissions visualization to confirm states separate into biologically distinct categories; redundant emission profiles at high N indicate over-segmentation and call for a smaller state count. When comparing an independently trained model to Roadmap or full-stack references, map states by emission similarity rather than by state number, because independently trained models do not share label ordering.

## Functional Enrichment

Test each chromatin state for enrichment against external genomic feature sets to validate that learned states correspond to expected biology and to reveal unexpected associations. ChromHMM provides two enrichment commands. OverlapEnrichment computes enrichment of each state for overlapping feature sets (CpG islands, repeats, conserved elements, etc.) supplied as BED anchor files. NeighborhoodEnrichment computes enrichment relative to anchor positions such as transcription start sites, supplied as position files. Prepare the appropriate anchor files before running.

## Alternative Segmentation Approaches

Apply alternative tools when ChromHMM's binarization is limiting or when cross-cell-type consistency, continuous-signal resolution, or multi-biosample visualization is the priority. Segway trains a dynamic Bayesian network on continuous bigWig signal (higher resolution, magnitude-aware) via train/posterior/identify. EpiSegMix uses flexible read-count distributions with duration modeling to handle both narrow and broad marks in one model. The full-stack ChromHMM (Vu & Ernst 2022) applies a precomputed 100-state model trained on 1032 datasets to new binarized samples via MakeSegmentation for comprehensive cross-tissue annotation. EpiLogos visualizes existing ChromHMM/Segway segmentations across many biosamples. IDEAS performs cell-type-aware joint segmentation across cell types. Choose based on whether continuous signal, cross-cell-type consistency, or visualization is the priority.

## Troubleshooting & Validation

Diagnose and fix common segmentation failures and runtime errors. Key failure modes include: 200 bp bins too coarse for sharp boundaries (reduce bin size); binarization discarding signal magnitude (switch to Segway or EpiSegMix); wrong state count producing redundant or lumped states (retrain at multiple N, pick the smallest interpretable); mark panel mismatch when applying precomputed models (match exact marks and ordering, or retrain); IgG control used instead of input (use sonicated input); and cross-cell-type state label inconsistency (use joint segmentation or a single precomputed model). Common runtime errors include JVM out-of-memory, slow BinarizeBam on unindexed BAMs, empty segments for chromosomes missing from the chromsizes file, and all-zero binarization from poor signal or control normalization. Reconcile disagreements between ChromHMM and Segway by inspecting emission matrices and matching resolution needs; bivalent TSS/polycomb overlap at promoters is expected biology in ESC-like cells, not an error.
