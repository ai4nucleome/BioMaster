# Bioskills Normalization

## Overview

The Expression Matrix Normalization workflow transforms raw integer count matrices into scaled, comparable values suitable for downstream analysis. Its central concern is composition bias: when a few highly-expressed genes consume a disproportionate share of reads, naive library-size normalization makes every other gene appear downregulated. Robust methods (TMM, RLE/median-of-ratios, upper quartile) estimate scaling factors from the majority of non-differentially-expressed genes, which is robust to the minority of DE genes.

Inputs: a raw integer count matrix (genes x samples/cells) plus sample metadata and a design formula; optionally gene lengths and GC content for within-sample and bias-correction steps. Outputs: per-sample size factors, normalized count matrices, variance-stabilized matrices for visualization, and (for single-cell) per-cell size factors and log-normalized expression.

Use this skill when you have raw counts and must choose and apply the correct normalization for a given task. A normalization decision table guides the choice: DE analysis with DESeq2 uses RLE internally from raw counts; edgeR/limma-voom use TMM; PCA/heatmaps/clustering use VST or log-CPM; WGCNA and ML use VST(blind=FALSE); GSVA/ssGSEA use log2(TPM+1) or VST; reporting expression uses TPM; cross-sample comparison uses DESeq2 normalized counts; single-cell uses scran deconvolution.

Critical rule: DE tools (DESeq2, edgeR, limma-voom) normalize internally from raw counts. Never provide pre-normalized, FPKM, TPM, or VST data to these tools. Common mistakes to avoid include using FPKM for cross-sample DE, applying log2(counts+1) globally instead of a proper variance-stabilizing transform, normalizing single-cell data with TMM (high dropout violates its assumptions), forgetting filterByExpr in edgeR (inflates multiple-testing burden), and using blind=TRUE VST for downstream analyses (over-shrinks by ignoring the known design).

## Pre-Filtering

Remove genes with insufficient expression before normalization to reduce noise and the multiple-testing burden. edgeR requires explicit, design-aware filtering via filterByExpr, which sets CPM thresholds based on the smallest group size in the design (min.count=10, min.total.count=15 by default) and is more principled than arbitrary cutoffs. DESeq2, by contrast, performs automatic independent filtering at the results() step, so manual pre-filtering there is purely for computational speed and memory and does not affect statistical results. Apply filtering before estimating size factors or dispersion. Forgetting filterByExpr in edgeR inflates the multiple-testing burden because its quasi-likelihood pipeline lacks DESeq2's independent filtering.

## Between-Sample Normalization

Estimate per-sample scaling factors that correct for library size and composition bias. RLE / median-of-ratios (DESeq2) builds a geometric-mean pseudo-reference across all samples and takes the median of per-gene ratios between each sample and the reference; the median is robust to the minority of DE genes, and genes with zero counts in any sample are excluded from the geometric mean. TMM (edgeR) selects a reference sample, computes gene-wise log-ratios (M-values) and average expression (A-values), trims the extremes (30% of M, 5% of A by default), and takes a weighted mean scaling factor; effective library size is lib.size times norm.factors. Upper quartile is a simpler alternative adequate when composition bias is mild. Special cases use type='poscounts' (high zero-inflation), type='iterate' (very small libraries), controlGenes (known stable genes or mostly-DE genomes), or spike-ins. These factors feed DE tools internally; export normalized counts only for visualization or reporting.

## Within-Sample Normalization (TPM/FPKM)

Convert counts to within-sample comparable units so that gene A can be compared to gene B within one sample. TPM divides each gene's count by its effective length (in kilobases) to get RPK, then scales each column to sum to 1 million. FPKM/RPKM is more problematic: Wagner et al. (2012) showed average FPKM varies between samples even for the same genome, because the per-million factor depends on RNA composition. TPM partially fixes this by normalizing to a constant sum, but it still represents relative abundance within a sample's sequenced population, not absolute abundance. Neither TPM nor FPKM should be used for differential expression testing. Use TPM for reporting expression levels and for GSVA/ssGSEA with precomputed matrices.

## Variance-Stabilizing Transformations

Transform counts so that variance is approximately constant across the mean range, producing matrices suitable for PCA, heatmaps, clustering, WGCNA, and machine learning. VST (DESeq2) is fast and the default choice; it fits the dispersion-mean trend and applies a variance-stabilizing function. rlog handles widely varying library sizes (>10-fold range) and low-count genes better via per-gene shrinkage, but it is slow (O(genes x samples)) and impractical beyond ~100 samples. The blind parameter controls whether the design is used during dispersion estimation: blind=TRUE re-estimates dispersions ignoring the design and is for unbiased initial QC; blind=FALSE uses dispersions from the full model and is recommended for all downstream use (heatmaps, WGCNA, ML) because it preserves biologically meaningful variance. edgeR's log-CPM with a prior count is the edgeR/limma equivalent; the default prior.count=0.25 suits statistical use, while a larger prior (2-5) dampens low-count noise for visualization. Never use transformed values for DE testing, as they lose the count-distribution properties DE tools require.

## GC Content and Gene Length Bias Correction

Correct sample-specific GC-content and gene-length bias that standard TMM/RLE normalization does not address. These biases arise from library preparation (fragmentation, PCR) and create systematic read-coverage differences correlated with gene properties; they are especially problematic for gene set enrichment analysis, where uncorrected gene-length bias causes recurrent false positives. EDASeq performs two rounds of full-quantile normalization: first within GC-content bins per sample (withinLaneNormalization), then between samples (betweenLaneNormalization). cqn (Conditional Quantile Normalization) combines GC and length correction with quantile normalization and returns a glm.offset that can be used directly in edgeR. Apply these when GSEA or gene-property-correlated analyses are planned.

## Single-Cell Normalization

Estimate per-cell size factors robust to the high dropout and zero-inflation of single-cell data, where bulk TMM/RLE fails because most genes are undetected in most cells (violating the assumption that most genes are detected in most samples). scran uses a deconvolution approach: it pools cells in overlapping windows sorted by library size, computes pool-level size factors, and deconvolves them back to individual cells. Rough pre-clustering via quickCluster prevents mixing cell types with very different transcriptome sizes, which would confound the pooling. scanpy's normalize_total plus log1p is a simpler CPM-like normalization that works for exploratory analysis but does not handle composition bias as well as scran; for rigorous analysis, run scran via rpy2 or anndata2ri.
