# Bioskills Deep Learning Atac

## Overview

This workflow applies sequence-based deep learning to ATAC-seq data for three tasks where classical MACS/TOBIAS pipelines fall short: Tn5 bias correction, variant (SNP) effect prediction, and de novo motif discovery. The primary tool is chromBPNet, a two-track CNN (bias model + accessibility model) that takes 1-5 kb DNA windows and predicts per-base Tn5 cleavage profiles plus total counts. Inputs: a coordinate-sorted, deduplicated ATAC BAM, a reference genome FASTA, chromosome sizes, a narrowPeak file of called peaks, and a BED of non-peak background regions; for variant scoring, a TSV of candidate SNPs. Outputs: a bias-corrected per-base accessibility model (Keras .h5), per-SNP log2-fold-change effect scores, and TF-MoDISco motif clusters matched against known databases (JASPAR/HOCOMOCO). Use this workflow when (a) interpreting GWAS or candidate SNPs for chromatin effects, (b) discovering cell-type-specific cooperative motifs beyond JASPAR, or (c) correcting Tn5 bias in low-input or low-complexity sequence contexts where TOBIAS ATACorrect underperforms. For standard peak calling and differential accessibility, prefer classical MACS3/DESeq2 pipelines instead. The workflow assumes GPU access (1 A100 recommended for training, ~24 h per cell type; inference can run on V100) and verified package versions for chrombpnet, tangermeme, tfmodisco-lite, and the kundajelab/variant-scorer companion repo. Deep-learning tooling evolves rapidly; verify signatures against the installed package and adapt rather than retrying on errors.

## Tool Selection and Environment Setup

Choose the appropriate deep-learning tool based on the analysis goal and verify package versions before running anything. chromBPNet is the default for bias correction, variant scoring, and motif discovery; scBasset for per-cell sequence-based predictions; EnFormer or Borzoi for long-context distal regulation and cross-cell-type prediction; tangermeme for fast inference-only variant scoring on an existing saved model. Deep-learning tooling evolves rapidly, so check chrombpnet, bpnet-lite, scBasset, tangermeme, tfmodisco-lite, captum, and the underlying TensorFlow/PyTorch versions, and confirm CLI flags with --help. If a call throws unexpected errors, introspect the installed package and adapt rather than retrying blindly. For most standard ATAC analysis (peak calling, differential accessibility) classical pipelines remain primary; deep learning enters when variant interpretation, cell-type prediction beyond observed data, or high-quality bias correction is the goal.

## Data Preparation and Chromosome Splits

Assemble the required inputs for chromBPNet training and generate train/valid/test chromosome splits. Required inputs: a coordinate-sorted, deduplicated, indexed ATAC BAM; the reference genome FASTA plus its .fai index; chromosome sizes; a narrowPeak file of called peaks; and a BED of non-peak background regions. Pre-filter the peaks file to remove chrM, ENCODE blacklist regions, and any empty entries because chromBPNet does not auto-filter and will fail to converge if these are present. Then run chrombpnet prep splits to produce a JSON fold file; train chromosomes are auto-inferred as those not listed in the train/valid flags, and the -tecr flag does not exist and must not be passed. The resulting fold JSON is consumed by both the bias and accessibility training commands.

## Bias Model Training

Train the Tn5 bias model on background (non-peak) regions. The bias model captures sequence-specific Tn5 cutting preference and is mostly cell-type-invariant, but chromatin-context contributions at cut sites can vary, so a per-cell-type bias model trained from a naked-DNA control is preferred when available. If no naked-DNA control exists, fall back to the chromBPNet authors' pre-trained K562/GM12878/HepG2 bias models and acknowledge the degraded performance, especially at cell-type-specific regulators (CTCF footprints will still look correct). The bias scaling factor -b controls how strongly the bias track influences training; chromBPNet docs recommend 0.5-1.0 depending on enrichment. This step requires sufficient data: fewer than 50M deduplicated nuclear reads or 30k peaks typically causes unstable training; pool replicates or reduce model capacity (--num-filters) if needed. If training fails silently and bias.h5 is missing, re-run with verbose output and check the input BAM size.

## Accessibility Model Training

Train the chromBPNet accessibility model with bias correction using the bias model from the previous step. The model is a dual-head CNN that predicts both the per-base Tn5 cleavage profile and total counts, with the bias model's contribution subtracted so the accessibility head learns chromatin-driven signal. Use the same fold JSON, peaks, and non-peaks as the bias step. The output is a Keras .h5 model; the bias-free variant (chrombpnet_no_bias.h5) is the one used downstream for variant scoring and contribution analysis. Training takes roughly 24 hours on a single A100 with 80 GB RAM for one cell type. For labs without sustained GPU access, prefer a pre-trained model from the ENCODE chromBPNet model zoo and skip retraining when the target cell type is covered. If the predicted profile is constant the model has collapsed (training too short); increase epochs and verify peaks are non-empty.

## Variant Effect Prediction

Score the effect of SNPs on predicted accessibility using the trained chromBPNet model. Two complementary paths exist. The first uses the standalone kundajelab/variant-scorer companion repo, because the chrombpnet snp_score subcommand is commented out in current chrombpnet/parsers.py and must not be used; it takes a variants TSV and emits per-SNP log2-fold-change magnitudes. The second uses tangermeme's substitution_effect for fast marginal ref-vs-alt scoring at each SNP, suitable for batch GWAS scoring. For GWAS variant prediction use marginal scoring at the SNP (matches phenotype-genotype coupling); for motif discovery use in silico mutagenesis (saturation across the window). Define the calculation explicitly because marginal and ISM scores have different magnitudes and answer different questions. Center each variant in its window; variants outside the model's effective window cluster near zero. |log2fc| > 1 is typical for strong-effect SNPs in regulatory regions. For motif marginalization (inserting a candidate motif into background sequences) use tangermeme.marginalize.marginalize; note that marginal_predict is not a real function name.

## Motif Discovery with DeepLIFT and TF-MoDISco

Discover de novo motifs from the trained chromBPNet model using per-base contribution scores. First extract one-hot sequences and DeepLIFT/SHAP contribution scores from chromBPNet (chrombpnet contribs_bw writes hypothetical contributions; convert to numpy via shap_to_modisco). Use DeepLIFT with the rescale rule (chromBPNet default) for TF-MoDISco because it preserves additivity; reserve Integrated Gradients for cases where DeepLIFT fails on saturating activations, and document the choice. Then run tfmodisco-lite (the maintained jmschrei/tfmodisco-lite, pip install modisco-lite) via its CLI; the original kundajelab/tfmodisco package with TfModiscoWorkflow is unmaintained and incompatible with modisco-lite. Finally generate an HTML report annotated against a known motif database (JASPAR or HOCOMOCO in MEME format). If TF-MoDISco produces too many small clusters, tighten target_seqlet_fdr to 0.01 or increase flank_size. Validate discovered motifs against JASPAR/HOCOMOCO before publication; TF-MoDISco can find composites and cooperative motifs that ChIP-validated databases miss. Runtime is roughly 6 hours on 32 CPU cores for 1M peaks.

## Cross-Tool Validation and Reconciliation

Reconcile disagreements between deep-learning predictions and classical pipelines, or between deep-learning tools, before reporting results. chromBPNet may predict a strong variant effect where MACS does not call a peak; the sequence model captures latent regulatory potential, so trust it for variant effect but not for peak calling. EnFormer and chromBPNet can both be correct at the same locus because they use different context windows (196 kb vs 1-2 kb) and cell types; report both with their context size. TF-MoDISco motifs that differ from JASPAR are not necessarily wrong, since TF-MoDISco finds composites and cooperative motifs; check JASPAR for confirmation. chromBPNet bias correction is more accurate but slower than TOBIAS ATACorrect, and TOBIAS remains publishable for standard use. The operational rule for high-confidence variant prediction is agreement across two approaches (chromBPNet plus EnFormer or Borzoi); single-tool calls should be reported as exploratory. For motif discovery, validate TF-MoDISco hits against JASPAR/HOCOMOCO before publication.
