# Clawbio Nfcore Scrnaseq Wrapper

## Overview

The clawbio-nfcore-scrnaseq-wrapper skill runs upstream single-cell RNA-seq preprocessing from raw FASTQ files using the nf-core/scrnaseq Nextflow pipeline. It takes a samplesheet CSV (required columns: sample, fastq_1, fastq_2; optional: expected_cells, seq_center, sample_type, fastq_barcode, feature_type) and produces canonical outputs including .h5ad count matrices, MultiQC reports, pipeline_info execution traces, and a full reproducibility/provenance bundle.

Use this skill when you need to go from raw 10x Chromium (or other supported chemistry) FASTQs to an analysis-ready .h5ad for downstream clustering, embedding, or annotation. It supports six aligner presets — standard (simpleaf/alevin-fry), star (STARsolo), kallisto (kb-python/BUStools), cellranger, cellrangerarc, and cellrangermulti — and validates the environment, samplesheet, and references before launching Nextflow. A demo mode runs the nf-core test profile with no user data required.

Do NOT use this skill if you already have a processed count matrix or .h5ad — route directly to scrna-orchestrator (for clustering, QC, markers) or scrna-embedding (for scVI/scANVI batch integration) instead. This skill does not perform normalization, clustering, marker detection, or dimensionality reduction; it only produces the .h5ad and hands it off.

The wrapper executes a strictly ordered pipeline: preflight validation, configuration, Nextflow execution, output resolution, and provenance/handoff reporting. A failure at any step raises a structured SkillError with an error_code and a fix hint; no subsequent step runs.

## Preflight & Validation

Before any Nextflow call, the wrapper validates the execution environment and all inputs. It resolves the pipeline source, preferring a local sibling scrnaseq/ checkout (pinned commit, audit-safe) and falling back to the pinned remote tag when no checkout is found or the checkout path contains whitespace (a macOS Docker restriction). It parses and validates the samplesheet CSV: resolving FASTQ paths relative to the CSV parent directory, normalizing sample-name whitespace to underscores, verifying readability and FASTQ extensions, rejecting FASTQ basenames with whitespace, enforcing consistent expected_cells (>=1) and seq_center for repeated sample rows, and rejecting exact duplicate FASTQ rows. It verifies Java (>=17) and Nextflow (>=25.04.0), comparing version tuples after zero-padding to three elements. It checks the selected backend (docker via 'docker info', conda/mamba binary location, singularity/apptainer interchangeably; wave and gpu need no binary check). It enforces protocol compatibility per preset (standard/star/kallisto require a non-auto protocol; standard rejects smartseq) and rejects conflicting reference configurations (--genome alongside any explicit reference flag raises CONFLICTING_REFERENCES). All subprocess calls have a 30-second timeout. A failure at any check raises a structured SkillError with an error_code and fix hint, and no subsequent step runs.

## Configuration

The wrapper translates the selected preset and CLI flags into a single effective params.yaml consumed by Nextflow via -params-file. All file paths use .as_posix() for forward-slash consistency across platforms. igenomes_ignore is automatically set to true whenever any explicit reference path (fasta, gtf, or any index) is provided, which suppresses nf-schema DNS validation of the default iGenomes S3 URL. Skip flags (--skip-cellbender, --skip-emptydrops, --skip-fastqc, --skip-multiqc, etc.) are only written to params.yaml when true, keeping it minimal. The wrapper also constructs the fixed nextflow run command with -params-file and -work-dir pointing into the output directory's upstream/work path. A normalized samplesheet copy with absolute POSIX paths is written to reproducibility/samplesheet.valid.csv. No arbitrary Nextflow passthrough is allowed — all configuration flows through the preset system and params.yaml.

## Execution

The wrapper launches nf-core/scrnaseq via subprocess.Popen with stdout and stderr piped to log files on disk (logs/stdout.txt and logs/stderr.txt), never buffered in RAM. It uses the local sibling checkout when available, or the pinned remote tag otherwise. On macOS with Docker, a macos_docker.config is automatically written to the reproducibility bundle and passed to Nextflow: it sets stageInMode='copy' (avoids VirtioFS EDEADLK), --platform linux/amd64 (Rosetta emulation), and routes STAR _STARtmp to the container's /tmp (avoids VirtioFS FIFO limitation). Output directories under /tmp emit a WARNING. On TimeoutExpired, the process is killed and EXECUTION_FAILED is raised. The --resume flag enforces strict compatibility: the wrapper checks that the stored manifest matches the current preset, profile, and pipeline source; mismatches raise INVALID_RESUME_STATE. The --demo flag forces preset=star and skip_cellbender=true since the nf-core test profile ships STAR-compatible data and CellBender does not work on small test datasets.

## Output Resolution

After the pipeline completes, the wrapper scans the upstream results tree to detect and classify all produced artifacts. It looks for MultiQC HTML reports, the pipeline_info/ directory (execution report, timeline, trace, DAG), .h5ad files (combined matrix preferred over per-sample, filtered preferred over raw), .rds files (SCE and Seurat formats), and CellBender-derived outputs. The wrapper selects a canonical preferred_h5ad when a combined filtered matrix is confirmed on disk. handoff_available is set to true only when preferred_h5ad is confirmed; if no combined matrix is produced and there are multiple per-sample files, handoff_available is false. Only artifacts confirmed on disk are reported — no hallucinated outputs.

## Provenance & Handoff

The wrapper writes a complete reproducibility and provenance bundle. It produces report.md (a run summary including the ClawBio medical disclaimer and a Next Steps section), result.json (a structured payload with preset, aligner, pipeline source, profile, preferred_h5ad, handoff_available, samples_detected, and cellbender_used), and provenance JSON files (inputs, invocation, preflight, upstream, outputs, runtime, skill). It also writes a SHA-256 checksum manifest (files only, never directories), environment.yml (conda environment spec for reference), a portable commands.sh replay script, and remap_paths.py for replaying on a different machine. When handoff_available is true, the report recommends the next ClawBio command using the preferred_h5ad: scrna-orchestrator for clustering/QC/markers, or scrna-embedding for scVI/scANVI batch integration. The --run-downstream flag opts in to automatic scrna-orchestrator handoff after pipeline completion.
