# Bioskills Peak Annotation

## Overview

This workflow annotates ChIP-seq / ATAC-seq peaks by assigning each peak to a genomic feature (promoter, exon, intron, intergenic), a target gene (via nearest-TSS or host-gene convention), and where applicable an ENCODE cCRE regulatory class (PLS / pELS / dELS / CTCF-only / DNase-H3K4me3). It also performs gene-set enrichment on the resulting peak-associated genes using regulatory-domain (GREAT) or locus-length-adjusted (ChIP-Enrich) methods.

**Inputs:** A peak file (BED / narrowPeak / broadPeak), a gene annotation (pre-built TxDb or a project GTF), and optionally an ENCODE cCRE BED from SCREEN.

**Outputs:** An annotated peak table (peak coordinates + gene symbol + feature category + distance to TSS), a cCRE classification overlay, and gene-set enrichment tables with volcano / region-gene association plots.

**When to use:** After peak calling and any differential-binding analysis, to interpret which genes and regulatory elements the peaks correspond to. Choose the annotation tool by context: ChIPseeker for standard genomes with pre-built TxDb, HOMER if already in the pipeline, pyranges for fine-grained control, GREAT / rGREAT for distal enhancer biology, ChIP-Enrich for promoter-focused marks with locus-length correction. For cell-type-specific enhancer-gene linking, prefer ENCODE-rE2G (see atac-seq/enhancer-gene-linking) over nearest-TSS.

**Critical conventions:** Match the annotation source to the alignment genome — a UCSC knownGene TxDb paired with GENCODE-aligned peaks causes silent mismatches; when a specific GTF is provided, use it directly via makeTxDbFromGFF. Decide explicitly between nearest-TSS (default, decouples gene from feature) and host-gene (overlap='all', internally consistent) conventions based on biology. BED uses 0-based half-open coordinates while GTF uses 1-based closed coordinates — convert before mixing to avoid one-base shifts.

## Annotation Source Setup

Choose the annotation tool and prepare its reference database. For standard genomes with pre-built annotations, use ChIPseeker with a TxDb package and an annoDb for automatic gene-symbol mapping. For custom or project-specific GTF, build a TxDb with makeTxDbFromGFF and plan to map gene symbols from the original GTF afterwards, since custom TxDb objects lack annoDb mappings. If HOMER is already in the pipeline, reuse its tag directory and annotatePeaks.pl. For fine-grained control over priority rules and distance calculation, use pyranges. Match the annotation source to the alignment genome explicitly — a UCSC knownGene TxDb paired with GENCODE-aligned peaks causes silent mismatches; when a specific GTF is provided, use it directly via makeTxDbFromGFF rather than a mismatched pre-built TxDb package. Decide the gene-assignment convention up front based on biology: nearest-TSS (default) for distal TF binding or reproducing HOMER results; host-gene (overlap set to all) for histone marks in gene bodies and custom GTF annotation. Handle coordinate systems carefully — BED uses 0-based half-open intervals while GTF uses 1-based closed intervals, and mixing without conversion shifts annotations by one base. Peak center is the midpoint of the BED interval; TSS from a GTF must be converted from 1-based to 0-based (subtract one on the plus strand, use the end coordinate on the minus strand); signed distance to TSS is negative when upstream.

## Gene-Feature Annotation

Assign each peak to a gene and a feature category (promoter, 5'UTR, 3'UTR, exon, intron, downstream, intergenic) using ChIPseeker's annotatePeak or HOMER's annotatePeaks.pl. In ChIPseeker, set the promoter window via tssRegion (c(-2000, 2000) is common; c(-3000, 3000) is the default) and the gene-assignment convention via the overlap argument (all for host-gene consistency, TSS for nearest-TSS default). The default feature priority is Promoter then 5'UTR then 3'UTR then Exon then Intron then Downstream then Intergenic, so a peak in both a promoter (gene A) and an intron (gene B) is classified as Promoter (gene A). For custom GTF, map gene symbols from the original GTF after annotation — strip GENCODE version suffixes (e.g. ENSG00000142192.25) before joining. In HOMER, the promoter window is hard-coded to -1kb / +100bp and is not configurable via flags; reclassify post-hoc using the Distance to TSS column if a custom window is needed. HOMER's primary output columns are 8 (Annotation), 10 (Distance to TSS), and 16 (Gene Name).

## ENCODE cCRE Classification

Cross-reference peaks against the ENCODE Registry of candidate cis-Regulatory Elements (cCREs) to classify each peak's regulatory context. The registry provides 2.35M human and 927k mouse elements in five categories: PLS (Promoter-Like Signature, within 200 bp of a TSS with high DNase and H3K4me3), pELS (Proximal Enhancer-Like Signature, within 2 kb of a TSS, enhancer-like with DNase and H3K27ac), dELS (Distal Enhancer-Like Signature, beyond 2 kb of a TSS), DNase-H3K4me3 (promoter signature without an annotated TSS), and CTCF-only (potential boundary element with DNase and CTCF). Download the cCRE BED from SCREEN, then intersect with peaks using bedtools where -wa preserves peak coordinates and -wb appends the matching cCRE class. Note that the master cCRE BED is cell-type-agnostic (the union across all cell types); for cell-type-specific activity claims, use the SCREEN web app or per-cell-type activity profiles rather than the master BED.

## Gene-Set Enrichment

Perform gene-set enrichment on peak-associated genes, choosing the method by peak biology. GREAT and rGREAT assign peaks to genes via regulatory domains (basal -5kb / +1kb around the TSS, extended up to 1 Mb in each direction or until reaching a neighbor's basal domain) rather than nearest-TSS, and each peak is assigned to all genes whose domain it overlaps — this makes GREAT most appropriate for distal regulatory elements such as enhancer ChIP or ATAC. ChIP-Enrich models locus length as a covariate to correct the systematic over-counting of long genes in standard enrichment; use it for promoter-focused marks (H3K4me3), and switch to broadenrich for broad marks (H3K27me3, H3K9me3) which accounts for region width. Filter hyper-ChIPable peaks (rRNA, housekeeping, mtDNA, top-1% input signal) before enrichment to avoid inflated ribosomal and translation GO terms. For non-vertebrate species, adjust GREAT's extension parameter since the default 1 Mb assumes vertebrate-scale regulatory distances.

## Troubleshooting & Reconciliation

Diagnose and fix common annotation failure modes, and reconcile disagreements between methods. ChIPseeker failures include: TxDb / annoDb genome mismatch (silent — verify with seqlevels equality; fix chr vs no-chr naming with seqlevelsStyle), default overlap set to TSS decoupling gene from feature (use overlap set to all for host-gene consistency), and custom TxDb returning NA symbols (map from original GTF, stripping Ensembl version suffixes). HOMER's hard-coded -1kb / +100bp promoter window requires post-hoc reclassification via the Distance to TSS column; a missing annotation means the genome is not installed. GREAT can inflate enrichment from hyper-ChIPable peaks (blacklist filter first) and its default 1 Mb extension is inappropriate for compact genomes. The master cCRE BED is cell-type-agnostic — do not use it for cell-type-specific claims. When methods disagree: ChIPseeker vs HOMER nearest-gene differences usually stem from different TSS references (RefSeq vs UCSC knownGene); GREAT vs ChIP-Enrich differences are expected (regulatory domain vs locus-length adjustment, both valid — use GREAT for distal regulatory, ChIP-Enrich for promoter-focused); enhancer peak nearest-gene vs ENCODE-rE2G target differences favor ENCODE-rE2G for cell-type-specific claims.
