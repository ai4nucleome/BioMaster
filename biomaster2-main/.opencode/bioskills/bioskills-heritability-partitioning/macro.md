# Bioskills Heritability Partitioning

## Overview

This workflow estimates SNP heritability (h2_SNP) from GWAS summary statistics (or individual-level genotypes) and partitions it across functional categories, cell types, and loci, then reconciles model-dependent enrichment estimates across LDSC and LDAK. Inputs: munged GWAS summary statistics, ancestry-matched LD reference scores, baseline-LD v2.2 annotations, optional chromatin BED files for cell-type prioritization, and (for HDL/HESS) reference eigen-decompositions or LD panels. Outputs: total h2 with intercept diagnostics, per-annotation enrichment and tau coefficients, per-cell-type p-values, cross-trait genetic correlations, LDAK-Thin reconciliation estimates, and per-locus h2. Use this workflow when you need to quantify how much heritability a trait carries, which functional categories or cell types concentrate that heritability, how two traits are genetically correlated, and which loci contribute most. The primary tools are LDSC (univariate, stratified, and cell-type), LDAK SumHer, HDL, and HESS. Method choice depends on the data regime (summary-stat vs individual-level; one-trait vs two-trait; total vs partitioned vs local) and the per-SNP-h2 model assumption (GCTA model vs LDAK-Thin). Operational rules: always report intercept, mean chi-square, and ratio jointly; use ancestry-matched LD scores (never apply EUR LD scores to non-EUR GWAS); and report BOTH LDSC and LDAK enrichment whenever enrichment is the primary claim, treating >2x discordance as model-dependent per Gazal 2019 and Hou 2019.

## Environment Setup & Reference Resources

Install the analysis tools and download the one-time reference resources before any heritability estimation. The LDSC official repository (bulik/ldsc) is Python 2.7 only and unmaintained since 2019, so use the abdenlab/ldsc-python3 v2.0.0 fork (belowlab/ldsc v3.0.1 broke the --h2/--rg/--h2-cts CLI) or run belowlab/ldsc via Docker. Also install LDAK 6+, HESS (Python 3 fork), HDL (R), BOLT-LMM, GCTA, and Popcorn. Download ancestry-matched LD scores (HapMap3), baseline-LD v2.2 annotations, 1000G EUR frequency files, weights, and multi-tissue chromatin ldcts from the Alkes group. Verify installed versions match the tested references before running, since CLI flag behavior differs across forks.

## Summary Statistics Munging

Convert raw GWAS summary statistics into LDSC's munged format (SNP, A1, A2, Z, N columns) using munge_sumstats.py. Harmonize alleles against the HapMap3 SNP list via --merge-alleles, supply per-SNP N through --N-col (or a fixed total via --N), and set effect direction with --signed-sumstats (BETA,0 for additive effect sign, Z,0 for Z-score, never both). Inspect the drop count: drops above 50% usually indicate allele mismatch or A1/A2 swap relative to the HM3 reference. Multi-allelic SNPs are dropped by design (LDSC requires biallelic). The munged file feeds every downstream LDSC analysis (h2, partitioning, cell-type, rg).

## Total SNP Heritability & Diagnostics

Estimate total SNP h2 with LDSC --h2 using ancestry-matched LD scores. Report intercept, mean chi-square, and the ratio statistic jointly, where ratio = (intercept - 1) / (mean_chi2 - 1). A ratio below 0.2 means inflation is mostly polygenic and h2 is trustworthy; a ratio above 0.3 warrants investigating population stratification, cryptic relatedness, or sample overlap before interpreting h2. Reject estimates as unreliable when mean chi-square is below 1.02 or h2 SE is 0.02 or above. For case-control GWAS, always supply --samp-prev (sample case fraction) and --pop-prev (population lifetime prevalence) to report liability-scale h2; without them LDSC defaults to the observed scale and typically underestimates by 2-10x. When the intercept exceeds 1.5, work through the troubleshooting ladder in order: refit with more PCs, remove cryptic relatedness, check case/control PC balance, check pairwise bivariate intercepts for overlap, and recompute with relatedness exclusion.

## Functional Category Partitioning

Partition h2 across functional annotations with stratified LDSC using the baseline-LD v2.2 model (Gazal 2017), which adds LD-related and MAF-dependent annotations to the baseline to control LD-MAF confounding. Use --overlap-annot to compute enrichment p-values and --print-coefficients for per-annotation tau coefficients. Apply Bonferroni correction at 0.05 divided by the number of annotations. Avoid testing highly collinear annotations jointly; test custom annotations marginal to the baseline (baseline plus the new annotation only) and report the VIF of the annotation matrix. Set an annotation size floor of at least 0.5% of the genome for tau estimation, since smaller categories are underpowered. Note that baseline-LD v2.2 is EUR-only; for non-EUR GWAS use baseline-LD-X (Atkinson 2021) or per-ancestry baseline-LD (Atkinson/Price 2022).

## Cell-Type Prioritization

Rank tissues and cell types by their per-annotation contribution to h2 using S-LDSC --h2-cts (Finucane 2018). Build per-cell-type LD scores from chromatin-marker BED files (H3K4me3, H3K27ac, H3K4me1, DNase, ATAC), compile a .ldcts manifest with one row per cell type (name, ldscore prefix, control ldscore prefix), and run --h2-cts against the baseline annotations. The trait-relevant tissue is the top-ranked tissue with p below 0.05 divided by the number of tissues (approximately 2.5e-4 for about 200 tissues). Published .ldcts files cover GTEx tissues, Roadmap epigenomes, immune cell types, and scATAC clusters. Custom cell types require computing per-cell-type LD scores from a chromatin BED via ldsc.py --l2, then adding a row to the .ldcts manifest. If no tissue passes threshold, the trait is underpowered for tissue prioritization; consider pooling related traits via MTAG.

## Cross-Trait Genetic Correlation

Estimate genetic correlation rg between two traits. Use HDL (R) as the primary estimator when samples are non-overlapping (below 5% overlap) for approximately 60% lower variance than LDSC, equivalent to about 2.5x sample size. Use cross-trait LDSC --rg when sample overlap exists, because the bivariate intercept (gcov_int) absorbs the overlap and the rg estimate remains unbiased; a non-zero gcov_int under known overlap is correct absorber behavior, not pathology, and should be reported alongside rg. For trans-ancestry genetic correlation use Popcorn, which requires effective N above 5000 per population. HDL's UKB reference requires non-overlapping samples; if either GWAS is from UKB, HDL is biased and cross-trait LDSC should be used instead.

## LDAK SumHer Reconciliation

Estimate h2 and functional enrichment under the LDAK-Thin model (Speed 2019) as a reconciliation check against LDSC's GCTA model. Reformat sumstats to LDAK input (Predictor, A1, A2, n, Z), run ldak --sum-hers against a build- and ancestry-matched LDAK-Thin tagging file, and optionally partition with the 86 continuous BLD-LDAK annotations. The GCTA model (LDSC) couples per-SNP h2 to local LD, while LDAK-Thin re-weights by MAF and LD with empirical exponents, so the two give systematically different enrichment estimates. Whenever functional enrichment is the primary claim, report BOTH LDSC and LDAK and flag the model assumption; treat discordance greater than 2x as model-dependent per Gazal 2019 and Hou 2019. For non-enrichment claims (total h2, rg) the model dependence is smaller and LDSC alone is acceptable. Tagging files are build-specific (hg19 vs hg38 are non-interchangeable); pre-computed files exist for GBR (HapMap), other ancestries require building via --calc-tagging.

## Local Per-Locus Heritability

Estimate per-locus h2 genome-wide with HESS using the LDetect partition (Berisa & Pickrell 2016). Step 1 computes per-chromosome quadratic forms on LD-projected effect estimates from an ancestry-matched LD reference; step 2 aggregates across chromosomes and constrains the estimate by the total h2 and SE from LDSC. Require at least 1000 SNPs per locus, since the quadratic form becomes unstable at lower density and yields negative or unphysical h2 with large SE; sparse loci should be dropped or merged with neighbors. HESS identifies high-h2 loci suitable for fine-mapping follow-up and supports bivariate local rg. Use ancestry-matched LDetect partitions (pre-computed for EUR, EAS, AFR).
