# Bioskills Co Accessibility

## Overview

Co-accessibility (cis-regulatory linkage) infers which enhancers connect to which promoters in scATAC data by exploiting cell-to-cell variability in joint accessibility of nearby peaks, without requiring RNA expression. Because single-cell ATAC is too sparse for direct correlation, the canonical tool Cicero aggregates cells into metacells, computes graphical-lasso correlation across a cis window (default 500 kb), and outputs peak-pair connection scores; ArchR's getCoAccessibility wraps Cicero inside the ArchR ecosystem, and SCENIC+ extends to TF-driven enhancer-gene networks when Multiome (ATAC + RNA) data is available. Co-accessibility is a statistical association, NOT 3D physical contact; it concords with Hi-C/Micro-C at ~30-50% but is not equivalent.

Inputs: a scATAC peak-cell binary matrix (rows = peaks, cols = cells) plus cell metadata, with peaks named in "chrN_start_end" format; optionally a Multiome RNA AnnData + pycisTopic object for SCENIC+, or published Hi-C/Micro-C loop calls (e.g. HiCCUPS) for orthogonal validation. Outputs: a peak-pair (or peak-gene) connection table with co-accessibility scores, thresholdable into enhancer-gene candidate pairs, plus arc-plot / genome-browser visualizations and Hi-C concordance statistics.

Use this skill when you have scATAC data and want cis-regulatory connections without 3D contact data. For physical contacts use Hi-C/Micro-C and the ABC model (see enhancer-gene-linking) instead; Cicero is the ATAC-only fallback. Connection thresholds typically 0.05-0.5; > 0.25 is high-confidence and should be calibrated against orthogonal Hi-C / HiChIP.

## Input Preparation

Build a Monocle3 CellDataSet (CDS) from the scATAC peak-cell binary matrix produced upstream by Signac or ArchR. Peaks must be named in the "chrN_start_end" format expected by Cicero, and both cell metadata and peak metadata (with genomic coordinates) are supplied to new_cell_data_set. This is the entry point for all Cicero-based co-accessibility inference; format mismatches (e.g. "chr:start-end" vs "chr_start_end") are a common failure mode and must be standardized here. For the ArchR path the input is an existing ArchR project that already contains a PeakMatrix (add addPeakMatrix() first if only a TileMatrix is present); for SCENIC+ the inputs are a paired RNA AnnData plus a pycisTopic cisTopic object and a motif-enrichment dictionary.

## Dimensionality Reduction & Metacell Aggregation

Reduce the CDS dimensionality with LSI followed by UMAP, then aggregate cells into metacells using make_cicero_cds with the UMAP coordinates. Metacells (default k = 50) overcome the sparsity of single-cell ATAC by pooling k neighboring cells so that accessibility correlation becomes statistically tractable. The k parameter trades off resolution against stability: too high a k on a large dataset makes make_cicero_cds slow or crash, while stochastic metacell aggregation causes connection counts to vary between runs (set a seed or raise k for stability). For heterogeneous datasets spanning multiple cell types, metacell aggregation dilutes cell-type-specific connections, so consider running Cicero per-cluster and combining results with cluster annotations.

## Co-accessibility Inference

Run Cicero's graphical-lasso correlation across the cis window to produce per-pair connection scores. run_cicero requires a genome chromosome-size data frame and parameters window (cis distance, default 500 kb) and sample_num (bootstrap windows, default 100). The graphical-lasso regularization alpha is normally data-driven via estimate_distance_parameter(), which fits a distance-correlation regression; manual override is rarely needed but very dense peaksets (>200k) may need higher alpha and very sparse (<10k) lower alpha. Output: a connection table with Peak1, Peak2, coaccess columns; positive = co-variation, negative = anti-co-variation. Distal connections beyond the window and all trans-chromosomal interactions are excluded by design. The ArchR path (addCoAccessibility / getCoAccessibility) wraps the same Cicero biology with ArchR's metacell aggregation and tighter default distances; SCENIC+ runs the full multi-step TF -> enhancer -> gene network inference and is significantly heavier (budget 1-2 days for setup).

## Connection Filtering & Visualization

Threshold the connection table to high-confidence pairs and visualize them. A working default cutoff is coaccess > 0.25 (Cicero documentation), but the optimal threshold is dataset-dependent and best calibrated against orthogonal Hi-C / HiChIP; typical thresholds range 0.05-0.5. Report total vs strong connection counts to sanity-check (expect ~10-50% of peaks to have at least one strong connection). Visualize strong connections as arc plots at a locus of interest using GenomicInteractions + Gviz, or as genome-browser tracks and peak-gene heatmaps via ArchR's plotBrowserTrack() / plotPeak2GeneHeatmap(). ArchR returns connections as a GRanges object compatible with GenomicInteractions for direct overlap with Hi-C loops.

## Hi-C Concordance Validation

Quantify what fraction of strong Cicero connections are supported by published Hi-C / Micro-C loop calls (e.g. HiCCUPS) as an orthogonal validation. Import the loop calls as GenomicInteractions, build a parallel object from the Cicero strong connections, and count anchor-anchor overlaps. Interpretation: > 50% overlap = high confidence (Cicero captures real 3D structure); 30-50% = standard (some 3D contacts don't vary in accessibility); < 20% = co-accessibility may not reflect contacts and lineage-specific contacts may be missing. Co-accessibility is a hypothesis generator; validate top candidates with Hi-C, ChIP-seq, or CRISPRi-FlowFISH. When Hi-C / Micro-C is available, prefer the ABC model (see enhancer-gene-linking) as the primary method and use Cicero only as an ATAC-only sanity check.
